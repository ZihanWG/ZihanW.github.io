Vulkan 实时渲染器（VulkanEngine）
角色：独立开发｜2025.09 – 至今｜关键词：GPU-Driven、Hi-Z 剔除、Clustered Forward+、Async Compute、CSM / VSM / Ray Query、Render Graph
C++20Vulkan 1.3GLSLGPU-DrivenRender GraphAsync ComputeVSMRay Query
  • 约 6 万行自有代码，基于 Dynamic Rendering、Synchronization2、VMA 构建 RAII 封装的 RHI 层。
  • GPU-Driven：Bindless 材质 + Multi-Draw Indirect，Compute 视锥剔除与两阶段 Hi-Z 遮挡剔除，在同一 dispatch 内完成离线 LOD 链选择。
  • 光照与阴影：Clustered Forward+（32 × 18 × 24 froxel）跑在 Async Compute 队列上，与阴影 pass 重叠；实现带缓存的 CSM、Virtual Shadow Maps（LRU 页表）与 VK_KHR_ray_query 光追阴影三条阴影路径。
  • Render Graph：由 pass 读写声明推导执行顺序、自动生成 Barrier、管理瞬态资源与生命周期，每帧校验实际录制与声明一致。
  • 性能与工程：自建 per-pass timestamp profiler 与 A/B 测量协议；曝光 pass 6.07 → 0.33 ms（直方图 + LDS 归约）；Sponza 1080p 整帧 3.78 ms（RTX 3080 Ti Laptop）；Catch2 + 三平台 CI（ASan/UBSan、lavapipe 图像回归）。
代码仓库 / README
可深挖点
  • 两阶段 Hi-Z 遮挡剔除、Compute 视锥剔除与 LOD 选择合并在同一 dispatch
  • Render Graph 执行顺序推导、自动 Barrier、瞬态资源与每帧录制校验
  • Clustered Forward+ 与阴影 pass 在 Async Compute 上的重叠
  • CSM / VSM / Ray Query 三条阴影路径的质量、显存与性能取舍
工程难点
  • 剔除与 LOD 选择移到 GPU 后，CPU 不再逐物体提交，需要保证间接绘制参数、可见性数据与 Hi-Z 两阶段之间的正确性。
  • Async Compute 与图形队列并行，需要 Render Graph 正确表达跨队列依赖与同步。
  • 三条阴影路径共存且可切换，便于在同一场景下对比质量、显存和耗时。
  • 性能结论依据 per-pass 时间戳和 A/B 测量协议，并用 CI 图像回归防止优化引入画面错误。
UE5 Path Tracer 软边 ShadowMask AOV（引擎源码修改）
角色：核心实现｜2026｜关键词：UE 5.7.4 源码、Path Tracer、面光源可见性、Sobol、TLAS、Movie Render Queue
C++HLSLUE 5.7.4Path TracingMovie Render Queue
  • 修改 UE 5.7.4 渲染链路，在 Path Tracer 首次弹射处对指定光源做面光源可见性采样，复用引擎的 Sobol 采样器与 TLAS shadow ray。
  • 与 Beauty 共享样本累积，经 Movie Render Queue 输出线性 EXR；功能关闭时零开销。
  • 自定义光源 ID 贯通 LightComponent → SceneProxy；配置错误时输出全无效 mask，而不是一张看似正常的错图。
  • 验证脚本显示 RMSE 约按 1/√N 收敛，重复渲染结果 SHA-256 一致。
可深挖点
  • UE 渲染数据流：LightComponent → SceneProxy → Path Tracer shader 的改动路径。
  • 为什么在首次弹射采样、与 Beauty 共享样本累积，以及如何保证关闭时零开销。
  • 如何证明结果正确：收敛曲线 + 确定性哈希，以及配置错误时“宁可无效、不出错图”的设计。
OpenGL 模块化渲染引擎（CGRenderEngine）
角色：引擎开发者｜2024.01 – 2024.08｜关键词：OpenGL、Shader/Material 系统、实例化、状态排序、PBR、阴影、HDR
C++OpenGLGLSLPBRHDR
  • 从零构建模块化 OpenGL 渲染引擎（PBR、阴影、HDR、Bloom、后处理），Scene 与渲染数据解耦。
  • 实例化 + 状态排序使 233 物体场景 draw call 从 442 降到 35（−92%）。
  • 实现 PBR、Shadow Mapping、Framebuffer 后处理、Tone Mapping 与基础调试流程，建立从 CPU 资源提交到 GPU 渲染输出的完整管线理解。
  • 扩展光线追踪与超采样实验，用于对比实时光栅化与离线渲染中的采样、阴影、反射和噪声收敛问题。
工程价值
  • 作为 Vulkan Engine 前置项目，系统训练 Shader、Material、Texture、Framebuffer 和 Post-process 的模块边界设计。
  • 通过实时光栅化与离线光线追踪对比，建立对渲染方程、采样、阴影质量和性能开销的统一理解。

UE5 渲染模块：多次散射 BRDF 能量补偿（Kulla–Conty）
角色：核心实现｜2025.01 – 2025.05｜关键词：PBR 模块、能量守恒、GGX、Monte Carlo、LUT、白炉测试、HLSL
C++HLSLUnreal Engine 5PBR
  • 基于 Kulla–Conty 多次散射思想实现 BRDF 能量补偿，改善高粗糙度 GGX 材质在单次散射模型下的能量损失问题。
  • 编写 Monte Carlo 积分工具生成 BRDF 补偿 LUT，以白炉测试验证能量守恒，并在 UE5 中通过自定义 HLSL 节点接入材质流程。
  • 对比 baseline GGX 与补偿后的材质表现，梳理 Fresnel、NDF、Geometry Term、split-sum 与 LUT 查表之间的工程关系。
面试价值
  • 能从渲染方程、微表面 BRDF、能量守恒和实时查表优化角度解释 PBR 模块，而不是只停留在材质效果展示。
  • 适合深挖 Monte Carlo 积分、LUT 预计算、split-sum approximation 与 UE 材质系统接入方式。

  • 可在同一场景下对比质量、显存占用和 GPU 耗时，讨论各方案适用场景。
